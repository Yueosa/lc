# 项目规则

## 项目边界

`lc init` 在当前目录创建 `.lc.json`。包含该文件的目录就是项目根。短注释和多行描述都保存在这一个清单中，路径相对于项目根，`.` 代表项目根目录自身。复制、移动或提交项目时，可以将清单一起带走。

`lc` 从当前目录向上查找最近的项目根。指定目录时，从该目录查找；指定文件时，从其所在目录查找。找不到项目根时，命令报错并提示使用 `lc init`。第一版只依赖项目清单，无需全局项目登记。

项目可以嵌套。子项目的文件和子项目根目录自身都归最近的项目管理：

```text
workspace/
├── .lc.json
├── docs/
│   └── guide.md
└── tools/
    └── converter/
        ├── .lc.json
        └── src/
            └── main.rs
```

在 `workspace/docs/` 中运行 `lc` 使用外层清单。从 `workspace/` 运行 `lc set tools/converter/src/main.rs "入口"`，则写入 `converter/.lc.json`。父项目的递归列表会标记嵌套项目并在边界处停止；批量检查和清理也遵守这个边界。导出指定目录时会遍历其中的嵌套项目，并在导出包中保留各项目的边界。

在已有项目的子目录运行 `lc init` 时，如果外层清单已有该目录或其后代的记录，命令会提示这些记录将被子项目遮蔽，并保留原记录，供用户决定是否迁移。清空外层项目也会保留这些被遮蔽的记录。

## 注释如何关联

注释描述项目相对路径的用途。同一路径被同类型文件替换时，注释保留。使用外部命令改名后，可以在清单中更新记录的相对路径。短注释和详细描述都保存在 `.lc.json` 中。

导出一个目录会收集整棵目录树的注释，包括嵌套项目。导入时按项目归属写回各级清单。

## 存储与兼容性

- `.lc.json` 使用 UTF-8，包含格式版本、项目相对路径、预期类型，以及可选的 Comment 和 Description。
- Linux 文件名按原始字节处理。有效 UTF-8 的路径保存为字符串，其他路径用带标记的 Base64 保存。清单和导入导出都保留原始路径字节，终端显示时转义无效字节和控制字符。
- 注释和描述使用 UTF-8。外部编辑器保存的内容如果无法按 UTF-8 解码，`lc edit` 会报错并保留原注释。
- 注释存储只依赖普通文件读写，无需文件系统支持扩展属性。
- 修改清单时使用同目录的 `.lc.lock` 对读改写加锁，在同一目录写入临时文件，再原子替换清单，避免并发修改互相覆盖或读取到半写入的 JSON。项目共享时只需要带上 `.lc.json`。
